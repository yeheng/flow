# 插件 UI 层设计（v1.1，含评审修正）

> 状态：设计稿 v1.1。v1 评审修正已并入：范围钉死单机、快照冻 UI 投影
> 本体、表单保存保留未知键、类型级校验口径改诚实、砍 `ref`、砍 i18n、
> 「零新增 RPC」改口为扩展现有列表。
> 从属 [2026-11-06-plugin-system.md](2026-11-06-plugin-system.md)。

## 0. 第一性原理与范围

**插件 UI 永远不是「和插件对话」**：执行插件只在 dispatch 期间存在，
插件在 UI 上的全部呈现只有两个来源——manifest（静态声明）与
journal/nodelog（已持久事实）。没有任何 UI 路径通往活着的插件进程。

红利：历史可渲染（插件不存在也行）、纯投影可测试、安全面为零。

**范围（v1 评审钉死）**：本设计覆盖 **ipc 单机模式**（master 与 runtime
共享 `FLOW_HOME/plugins/`）。remote 模式下 manifest 权威在 agent 侧，
见主文档 §10——那份设计依赖本节的「冻结 UI 投影」，但不改本节结构。

## 1. 一份 schema，三个消费者（口径修正）

manifest 参数声明驱动：web 表单（设计期）、服务端 publish 校验、CLI
校验。**校验实现只有一处：Rust 服务端**（manifest 解析器旁）；web 表单
只做即时提示，永远不是权威（TS 侧不复制校验逻辑）。

**校验口径（诚实版）**：类型级错误前移到发布时；语义校验仍在 dispatch
落 Business outcome。为此闭集补三个便宜属性：

- `number`：`min` / `max`；
- `text` / `code`：`max_len`；
- `required` 语义 = 存在且非空。

enum 漂移、跨字段约束这类语义校验永远在插件侧——文档不承诺做不到的事。

## 2. 四个 UI 面（接既有组件）

### 2.1 调色板（NodePalette）

`category`（宿主分类闭集）+ `icon_key`（宿主图标字典 key，非资源文件；
查不到回退缺省）。不给图片/颜色值，视觉注入在字典层挡掉。

### 2.2 节点参数表单（ModalFields + CodeEditor）

**widget 闭集（v1.1 修订）**：

| widget | 属性 | 渲染 |
| --- | --- | --- |
| `text` | `max_len`, `required` | input |
| `code{format: text\|js\|json\|shell}` | `max_len`, `required` | textarea / CodeEditor（`format:text` 即多行文本，**不另设 textarea**） |
| `number` | `min`, `max`, `required` | number input |
| `boolean` | — | select |
| `enum` | `values`, `default` | select |
| `secret` | — | 引用选择器（指向 secrets 存储，永不显示值） |

**v1 砍掉**（记录在案，防复活）：`ref`（引用域未规格化，先用 `text` +
宿主模板语法）；文件上传、日期、颜色、嵌套对象、条件显隐（新 widget =
宿主 UI 版本）。**i18n 不做**：manifest 字符串 literal-only 原样显示，
宿主没有 i18n 框架，不发明 key-or-literal 的坑。

**保存语义（v1 评审补，防数据丢失）**：

- 表单保存**必须保留 schema 之外的键**：读入 params → 渲染已知字段 →
  保存时把未知键 merge 回去。插件升级加了参数、schema 尚未刷新的场景
  下，表单编辑不得静默丢值。此条进 U2 验收用例。
- raw JSON 视图永远可用（schema 解析失败/版本不认识/看真身），与表单
  视图切换不丢数据。
- 表单值类型转换（ModalFields 的 string 值 → number/boolean）在保存点
  做一次，不散在各字段。

### 2.3 运行详情（NodeInspector）

不发明新面板。插件声明 `[ui.run_view] summary_keys`；NodeInspector
输出区按声明挑 key-value。**遍历规格**：单级 dot-path（`agent.model`），
缺失键跳过，不遍历数组。日志/attempt/状态现状原样（进度早已走 nodelog）。

### 2.4 插件配置页

`[config]` 声明 + 同一套 widget 闭集渲染 + journal 存储 + run 快照冻结
（主文档 §5）。`secret` 在参数级与配置级两个域都是**对同一 secrets
存储的引用**，dispatch 时同一机制解析——不存在第二套秘密通道。

## 3. 声明的获取（改口：扩展现有 RPC，不是零新增）

web 获取 palette/params schema 走**现有节点类型列表 RPC 的扩展**：合并
内置类型 + 插件声明，携带 params schema。扩展走已审路径（订阅/背压/
鉴权已过审），不新开 RPC。运行数据继续走既有订阅（logsByNode/monitor）。

| 数据 | 权威存储 | 流向 |
| --- | --- | --- |
| 节点参数值 | 工作流定义（journal） | 表单 ↔ 定义 JSON；publish 校验 |
| 插件配置值 | journal + secret 引用 | 配置页 ↔ journal；run 快照冻结 |
| 运行数据 | journal / nodelog | 既有订阅 |
| palette / schema | manifest（单机：插件目录；remote：agent 上报，见主文档 §10） | 扩展的节点类型列表 RPC |

## 4. 版本化与兼容（v1 评审钉死）

- **run 快照冻结 manifest 的 UI 投影**（palette/params schema/
  summary_keys 的 JSON，几 KB），随既有 run 数据下发。渲染只看快照，
  永不回读插件目录——插件升级、卸载、agent 消失都不影响历史渲染。
  （冻「版本号」是指针不是本体，v1 的写法实现不出「历史可渲染」。）
- **版本解析时机**：run 用**当前启用版本**的插件执行（不做 per-workflow
  版本钉死）；publish 校验当时版本；**插件升级时对已发布工作流批量
  重校验**，不兼容的工作流标记并在 run 启动时明确拒绝，错误点名
  「插件升级导致」。不静默、不猜。
- manifest 加字段/widget 兼容（忽略+日志）；字段改名/删除 = 不兼容。

## 5. 演进规则

| 未来需求 | 正确动作 |
| --- | --- |
| 新 widget | 宿主 UI 版本 + ModalFields 扩展，全插件受益 |
| 活插件面板 | 先回答「历史 run 怎么渲染」：只对活 dispatch 中继，历史降级持久数据 |
| 插件自带前端 | = 产品插件宿主（主文档 P4+），另一个架构决策 |
| i18n / `ref` | 各自的前提成立时再进闭集（宿主有 i18n 框架 / 引用域被真实需求逼清楚） |

## 6. 落地切片

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| U1 | manifest 解析 `ui.*`（闭集校验、min/max/max_len）+ **run 快照冻结 UI 投影** | 单测：解析/拒绝/快照含投影 |
| U2 | web：palette/表单接 manifest（harness 试点） | **未知键保存不丢**用例；raw↔表单切换不丢数据 |
| U3 | 服务端 publish 校验（Rust 唯一实现）+ 插件升级批量重校验 | 语义错误仍走 dispatch 的契约测试 |
| U4 | NodeInspector summary_keys + 快照投影渲染 | 插件卸载后历史 run 详情仍可渲染 |
