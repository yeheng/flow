## 1. 不变需求与分期决策

1. JSONL 是完整业务历史的唯一权威，SQLite、检查点和索引可删除重建。
2. 主进程独占权威提交。**一期保留现有进程内节点执行；二期才通过 spawn 和本地 Unix socketpair 隔离执行；三期才接入远程 agent。** 分期改变交付顺序，不改变最终方向。
3. 最低目标为 **1000 个同时在飞 run**，与 runs/s、事务/s、编码字节/s 分开度量。等待中的 run 不等于活跃执行任务；一期分别限定 `R_max` 与 `A_max`，二期再增加进程槽位及 IPC 窗口预算。
4. 节点实际执行输入、实际输出与数据流动均完整保存，不以配置预览代替实际值；去除写入侧截断与全局键名脱敏。声明凭证保存引用，展示/导出按读取授权处理。
5. console/stdout/stderr/引擎叙事属于可丢弃观测数据，使用独立有界存储；不占 audit_seq、不参与权威结果屏障或完整性结论。
6. 持久业务等待释放活跃执行资源；外部结果未知不能盲重试。重放只归约已提交事实，不重新运行 JS 或发 HTTP。

此前六项精简继续有效：一个节点尝试内准备并执行、Intent/Authorized 同事务、单行有界事务、连续 chunk 的固定 ValueRef、仅 projected 写入成功语义、按代表性负载验收性能。传输消息及子进程生命周期从一期移出。

## 4. 一期进程与模块结构

```text
API / webhook / cron
          |
          v
同一 flow-server 进程
  命令与 DAG 协调器 ----> 有界进程内节点任务（exec / expr）
          |                        |
          +--- 内部提交/授权门面 <---+ 实际输入、分块、结果
                     |
               JournalWriter ---> SQLite Projector ---> 查询 API
                  唯一 writer           可重建

  独立有界观测存储 <--- console / 引擎诊断
```

一期只需新增 flow-journal；Driver、内部提交门面、现有执行代码和观测存储在现有 crate 中按职责组织，不引入通用插件或网络 Transport 框架。文件 I/O/fsync 可在独立任务/线程，只有 JournalWriter 持有权威文件写句柄，调度循环不阻塞在同步磁盘调用上。

内部门面提供事实提交、操作授权、结果接受和值读取；返回值/await 完成表达持久提交结果。执行任务不得直接绕过门面修改 store 或文件。二期把进程内执行适配器替换为 IPC 适配器，复用业务提交规则；一期不定义 wire DTO、进程会话或远程路由。

<a id="plan-s5-0"></a>
### 5.0 golden source 与可观察性的硬边界

本节落实 §1 第 4–5 条的完整业务事实与观测边界，先于本章其他条文生效。两类记录必须语义分离，不得混流：

| 记录类别 | 是否 golden source | 可丢弃 | 序号与持久化约束 | 存储要求 |
| --- | --- | --- | --- | --- |
| 节点实际执行输入、实际输出、节点间数据流动 | 是 | 否 | 执行任务来源用 audit_seq；主进程来源用 lsn；均须持久后使用 | 完整；不截断、不脱敏 |
| workflow 定义、配置、命令、请求身份、等待、裁决、父子关系 | 是 | 否 | 主进程事务 lsn，持久后生效；不占执行任务 audit_seq | 完整 |
| 大内容的 chunk 与完整性描述 | 是 | 否 | 执行任务来源用 audit_seq；全部块持久且描述发布后可用 | 完整，按 §6.1 分块 |
| 外部操作 Intent / Authorized / Outcome | 是 | 否 | Intent/Authorized 为主进程同一事务；Outcome 占执行任务 audit_seq，结果须过屏障 | 完整 |
| `nodelog`：console / stdout / stderr / 引擎叙事 | **否** | **是** | **否** | 有界预算，可采样、可限幅、可丢弃；落地在独立观测存储（F13） |
| 主机地址、监听端口等启动配置 | 否（非业务事实） | 是 | 否 | 不进权威日志 |
| 凭证明文 | 否 | — | 否 | 只存凭证引用，不进日志正文 |

由此产生的硬约束：

- **可观察性记录不得进入权威事务流，且必须有一块独立的观测存储承载（任务 F13）。** run timeline / 订阅里的 console 行是产品视图的硬需求，因此这不是可选项：可观察性记录由 journal 之外的**独立有界观测存储**承装，可跨主进程重启读回，**不得写入 journal 权威事务、不得消耗 audit_seq、不得参与 §7 的持久结果屏障与完整性判定**。观测存储有独立字节上限，可轮转、可整段丢弃；它的丢弃、采样、截断都不改变 run 的业务状态、输出与完整性字段，展示层必须标明被丢弃的量。禁止为了省事把可观察性行塞回 journal 或投影表。
- **golden source 记录不得降级为观测记录。** 不得以体积、频率或“反正是日志”为由，对本节表中的权威业务记录做采样、截断、脱敏或按级别丢弃。写入跟不上时按 §8 背压，而不是丢弃。
- **脱敏只发生在读取与导出，且按声明式凭证清单判定。** 现存写入前脱敏（`redact_value`）与输入截断（`cap_input_snapshot`）在 v2 写入路径中必须移除。移除的对象是**全局子串键表**（`nodelog.rs:198` 的 `authorization/cookie/token/password/secret/api_key/apikey`），它今天把 `my_auth_token` 这类合法业务字段也脱敏成 `***`，是 bug。v2 的规则是：只有命中**节点描述符声明的凭证参数**（`NodeType::secret_params()`，`model.rs:302`，`secrets.rs:40,77` 已在用）才不落明文、只存凭证引用；其余业务值一律按实际值原样落盘，包括键名恰好含 `token`/`secret` 的业务数据。展示层与下载接口各自的脱敏策略另行定义，但下载/审计接口必须能取到完整实际值（§5.1）。
- **凭证与业务值分开。** 按 §5.1：权威日志记录凭证引用，不写密钥明文；这与“写入不脱敏”不矛盾——需要重放的业务值与访问凭证是两个集合。判定“某个值是不是凭证”的唯一依据是节点描述符声明，不是键名猜测；运行期由上游节点**作为数据**传进来的凭证属于业务值，按原样记录，这是“实际输入”语义的必然结果，必须在威胁模型中明示（见下条）。
- **journal 是系统内价值最高的数据存储，读取权限必须显式建模。** 移除写入侧脱敏并保留完整实际输入/输出，加上完整值流式下载接口，意味着 journal 与投影包含用户业务的原文。F02 必须固定：谁可以读取完整值（与 run 读取权限同源，不得因下载接口而放宽）、审计/下载路径的鉴权与审计留痕、运维与备份介质的静态加密要求，以及日志在磁盘上的访问控制。此项未固定不得开放完整值下载接口。

<a id="plan-s5-1"></a>
### 5.1 必须能够从权威日志重建的内容

- workflow 创建、更新、发布、删除及执行所用完整定义。
- run 输入、固定版本、父子关系、节点实际执行输入和结果。
- schedule/webhook 配置变更、触发身份和触发结果。
- run.start、signal、cancel 的请求身份、请求指纹与处理结果。
- 等待条件、wake_at、重试状态、人工裁决与隔离原因。
- 全部纳入契约的业务/审计记录，包括大内容的完整分块。

主机地址、监听端口等启动配置不是业务事实。凭证由既有秘密管理渠道提供；权威日志记录凭证引用，不能以“完整”为由默认写入全部环境变量和密钥明文。需要重放的数据与访问凭证必须明确分开，**切分依据是 `NodeType::secret_params()` 声明，不是键名子串匹配**（§5.0）。

完整性指按已定义审计 schema 捕获的原始内容不被存储层静默丢弃。用户界面可以分页、折叠或显示预览，但下载/审计接口必须可获得完整内容。现存的两条降级必须删除，不得保留为兼容行为：写入前脱敏（`redact_value`）与输入截断（`cap_input_snapshot`，8 KiB 上限）；journal 里保存的是**实际执行输入与实际输出**，脱敏与预览只在读取/导出侧实现。否则重放读取的输入事实与实际执行不一致。

<a id="plan-s5-2"></a>
### 5.2 核心标识

| 标识 | 语义 |
| --- | --- |
| journal_id / format_version | 数据集身份与格式版本 |
| lsn | 单调递增的事务序号；事务内事件以 `(lsn, event_index)` 定位 |
| tx_id | 一个原子逻辑提交；命令去重使用稳定请求身份 |
| run_id / run_seq | 运行身份与对外事件序号，保留按 run 订阅语义 |
| node_id / attempt | 节点身份与业务执行尝试 |
| node_execution_id | 节点逻辑激活实例，重试不变，再次合法激活时新建 |
| dispatch_id | 一次节点执行尝试的持久身份；一期绑定内存任务，二期绑定子进程，准备与执行共用 |
| operation_id | 本逻辑节点唯一的外部操作身份，跨不明结果重试不变 |
| permit_id | 一次尝试内的操作授权身份；一期用于内部去重，二期封装进许可消息 |
| audit_seq | 执行尝试内的审计序号，从 1 连续增长 |
| request_id + scope + fingerprint | 外部提交幂等身份，同键异参冲突 |

一期每个有副作用节点只允许一个外部逻辑操作。主进程维护 `(run_id, node_execution_id) → operation_id + request_fingerprint`，不引入多操作 operation_key 注册表。请求指纹覆盖实际目标、方法、业务参数和凭证引用，编码版本由 F02 固定；主进程按已提交实际输入和适配器契约核验，不能只信执行任务自报。同身份同指纹附着原操作，异参拒绝；更换 attempt/dispatch_id 不产生新 operation_id。显式新业务操作才分配新逻辑身份。

执行任务产生的实际输入、输出、响应分块等占 audit_seq；主协调器的命令、授权和裁决使用 journal lsn，不伪造执行任务序号。所有这些事实均受权威持久化约束。

<a id="plan-s5-3"></a>
### 5.3 重放契约

初版的重放指：按日志格式与事件语义版本归约已提交事实，重建定义、业务状态、等待和查询投影。重放不运行用户 JS、不发 HTTP、不重新产生外部副作用；缺失结果保留未决状态，不能现场执行来补历史。

计算复验是独立的可选能力：只有保存了实际输入、定义版本、执行代码 build、节点语义版本及时间/随机等非确定性依赖，才可在隔离环境复算对比。初版保存上述可获得的版本与实际执行输入，但不承诺任意旧脚本可确定性复算。外部业务重执行必须是显式命令，并区分原 operation_id 的核对/重试与新的业务操作。

日志 reducer 必须按事件版本分派；不支持的必需版本停止恢复，不能跳过。检查点不兼容可重建，不等于旧事件语义可以删除。迁移验收的“重放”均采用本节的无副作用状态重建定义。

### 6.1 单提交域，分段存储

```text
data/
  journal/
    00000001.jsonl
    00000002.jsonl
    ...
  checkpoints/        # 派生，可重新生成
  indexes/            # 派生，定位 run/控制记录/审计范围
  projection.sqlite  # 派生，可删除重建
```

每一物理行都是完整 JSON；内容中的换行按 JSON 转义。大字段用有序 chunk 记录表达，不能要求一次在内存中拼出无限大的 JSON 行。

日志行和事务共用同一个编码上限，起点 1 MiB（含包络及换行），分段目标 256 MiB；最终配置由 F02/F07 验证。大型值按连续 chunk 保存，所有权威内容仍位于 JSONL 中。

一期固定 `ValueRef = {journal_id, output_id, codec, version, chunk_count, total_bytes, digest}`；输入与输出都使用此描述，output_id 是对象身份。每块以 `(output_id, chunk_index)` 定位，index 从 0 连续增长；摘要覆盖按序拼接的、由 codec 定义的原始内容字节，total_bytes 不包含传输 base64 膨胀。派生索引可删除重建，不在 Ref 中存块数组、清单根或清单树，也不实现离散分块复用。

主进程流式检查块序、重复内容、总长度及摘要；全部分块持久化后用小事务发布固定描述，发布可与节点结果同事务完成。只有发布完成的描述能作为 StoredValue::Ref 使用。结果提交可携带候选描述，校验和发布前不能供下游消费；未完成对象保留为审计证据。输入同样限制块大小、总字节和校验资源；输入超出能力时派发前拒绝，实际输出超限则停止生产并记录明确失败及完整性，不能截断后报告成功。

**大值必须贯穿执行与状态层**（责任任务：[F02](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f02)、[F08](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f08)、[F10](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f10)、[F12](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f12)）：

- 定义内部版本化 `StoredValue = Inline(Value) | Ref(ValueRef)`；Inline 有编码字节上限，ValueRef 包含 journal_id、对象身份、codec/版本、总长度、摘要和 chunk_count。Ref 指向已提交且校验完成的内容，不能指向执行任务临时文件。run 输入、节点输出、准备结果、OperationOutcome、最终输出、投影和检查点统一使用此表示；归约和恢复只处理引用，不为恢复状态加载大对象。
- `RunState.outputs`、`NodeExecContext` 和 Driver 前驱输入快照改为持有 StoredValue，扇出只复制引用。start/end 透传沿用引用；多前驱汇合流式构造原有 JSON 映射并发布新对象，不能在主进程拼成完整 Value。DAG 条件所需的小型判定值随节点结果提交，不通过加载整个输出决定分支。
- HTTP/集成适配器从响应流增量捕获原始内容并写 chunk，在累计编码/解码字节、解析深度及资源上限内处理。禁止先 `.text()`/`.json()`/`.bytes()` 读完整响应再分块；无 Content-Length 或长度不可信也要逐块计量。保留现有 JSON body/文本回退语义：可流式验证并经主进程流接口重读已保存内容，不能为再次解析重发请求；必须完整解析的适配器须声明物化上限。超限保存已捕获前缀与失败/未决事实，不能将外部操作当作未发生后自动重试。
- JS 保持 `input`/`nodes` 的普通值语义，一期只在受限进程内 JS 上下文中按预算物化，二期再移入子进程。F02 分别固定 inline 上限、阶段总物化字节、JS heap/进程内存、输出总量及解码扩张限额；准入累加全部前驱和 run 输入，不能只检查每个对象。超限在执行用户代码前明确失败；解析和 JS→JSON 转换也受预算约束。流式节点可处理超过 JS 上限的内容，初版不承诺任意大 JSON 可直接交给 JS。
- 流式生产、传递、状态归约、透传和恢复的内存不随对象总量增长；JS 物化路径在声明限额内随输入增长。测试分别记录两者，不能用提交队列的有界内存代替整个节点链的验收。对外原值/引用协商见 §10.3。

<a id="plan-s6-2"></a>
### 6.2 一行一个有界事务，批量持久提交

一行保存一个完整事务，内部可包含多个业务事件：

```json
{"data":{"v":2,"journal_id":"j1","lsn":"41","tx_id":"t1","events":[{"kind":"example","run_id":"r1","run_seq":"1","payload":{}}]},"sha256":"<data 原始 UTF-8 字节的摘要>"}
```

行以 LF 结束；SHA-256 覆盖 `data` 值从起始 `{` 到配对 `}` 的原始 UTF-8 字节，不含外层包络、摘要字段与 LF。读取器保留原始片段，不能重新序列化后验证。包络字段、重复键拒绝规则与编码版本由 F02 fixtures 固定。序号和累计字节等大整数统一用十进制字符串，供后续 IPC 与当前 API 共用。lsn 按事务递增，事务内事件按数组顺序归约，事件定位用 `(lsn, event_index)`；run_seq 仍按 run 的公开事件递增。

一行一个事务，统一编码上限初值 1 MiB，包含全部字段与 LF。一个事务只占一个段；轮转仅在行边界发生。父子创建/等待等原子业务变更放在同一 events 数组；大值先通过多个有界事务提交连续 chunk，再用小事务发布引用。超限原子控制命令在产生业务效果前拒绝，不拆成半笔可见变更。读取器可在硬上限内缓冲一行，不按日志总量分配内存。

完整 LF、合法 schema 与正确摘要共同构成逻辑提交判定；不再使用 TxBegin/Record/TxCommit 跨行组装协议。**单次 write 并不保证原子性或耐久性**：只对完整校验的事务归约，fsync 成功后才确认；歧义尾部继续遵守 §6.4。恢复接受完整有效事务，即使原回执未知；重试查询原提交，不重复创建。摘要发现意外损坏，不承诺防篡改。

JournalWriter 把若干完整事务行组为一个写批次，一次 fsync 确认全部事务。起点为审计批次最多 512 KiB、group commit 主动聚合等待最多 5 ms；物理写批次另有总字节上限，由 F02 预算、F07 压测确定。聚合等待不包含排队、编码、I/O 与 fsync 时延。所有编码包络均计入相应上限；冻结配置在运行中不得临时突破，调参须在同等耐久条件下重新验证延迟与内存。

控制与审计队列均按字节有界，JournalWriter 在事务边界给予控制有限优先机会，审计按派发轮转，空配额可借用。控制不能饿死审计，审计洪泛不能饿死控制。一次事务写入不可抢占；同步失败进入存储不可用，不能靠调度掩盖故障磁盘。

**性能由工作负载决定。** 现提交器已按文件去重（`event.rs:293-300`），全局文件使跨 run 事务能共享一次 fsync，但不保证任何负载都能聚成大批。若提交速率为 λ 事务/s、平均每批 q 个事务，则数据文件 fsync/s 约为 λ/q，另计轮转/目录同步。q 由到达速率、批字节上限、聚合时限和背压共同决定；单次 fsync 微基准不能独立推导系统吞吐，也不能证明“任何批大小都救不了”。

F02 固定代表性负载：run/活跃任务数量、事务/s、编码字节/s、大小分布、控制与审计比例及突发模式，同时记录目标盘 fsync 基线作为诊断参考。F07 用真实提交器验证吞吐、控制/审计提交 p99、内存与公平性；F17 再验证一期全链路 projected 延迟和恢复。这些共同决定 go/no-go。

摊销比只在 F02 明确的高提交率、可组批场景中作为回归门槛，阈值由该场景预期批量与基线确定。低负载或 1000 个大多等待的 run 允许每批一个事务，以及时提交；不设置通用十倍摊销、并发增长斜率或微基准上限 80% 门槛。报告分别计数数据文件与目录 fsync、记录每批事务/字节及 fsync 时延分布。

若目标负载不达标，先定位瓶颈并在预算内验证批大小、聚合等待与实现优化；仍不达标再另行设计提交域。本文不预选分片或额外 WAL。任何后续布局都不能在完整事实尚未可从权威 JSONL 恢复时返回成功。

<a id="plan-s6-3"></a>
### 6.3 提交步骤与失败

1. 在主进程中校验命令、去重身份和当前状态，预留必要序号；同一业务对象的冲突命令串行裁决。冲突覆盖命令去重键、父子关系、外部操作身份/授权及派发结果/取消；前一命令提交并应用前，后一冲突命令不得依据旧状态通过校验。同幂等键的在途请求附着同一待提交结果；非冲突事务可以批量刷盘。
2. JournalWriter 写完整事务；可合并多笔完整事务后一次 fsync。
3. fsync 成功后推进 durable_lsn，才向内存状态机、投影器、订阅器发布提交结果。
4. SQLite 以事务应用一个或多个完整的已提交日志事务，并在同一事务更新 applied_lsn（投影游标）；禁止拆分单个日志事务，游标只能位于完整事务结束边界。
5. 需要执行的任务只有在对应执行开始事实提交后才能进入进程内执行；具体外部操作另经内部授权裁决。

文件创建、首次目录项、轮转及封口涉及的目录持久化必须纳入实现；不能只 sync 文件后宣称新文件在断电后一定可发现。按目标系统验证 fsync/目录同步语义，硬件遵守同步协议是耐久性前提。

写入或同步失败：停止新的派发/成功确认，不推进 durable_lsn；保存错误并进入存储不可用状态。不能在不明部分写入后继续追加猜测序号。关闭写入、重新读取并恢复到确定边界后才能恢复服务。

不能依赖追加另一条记录来“修复”一个未持久化事务；崩溃尾部由恢复规则决定。

<a id="plan-s6-4"></a>
### 6.4 崩溃尾部与损坏

- 故障模型区分进程崩溃/断电造成的未完成写入，与持久化后的截断、介质损坏或人为改写。单份日志不能可靠区分这两类故障的所有尾部形态。
- 完整有效事务按已提交处理，即使回执未知。完整事务摘要错误、段缺失/错序、封口段损坏均停止自动恢复，不跳过。
- 初版默认不自动删除歧义尾部：保留原文件及故障位置，进入只读恢复模式。普通崩溃留下半条尾记录也可能触发人工修复，因此本方案不承诺所有进程崩溃后都自动恢复可写服务；F02 必须明确此运维代价并确定恢复时间目标。离线 repair 必须先保存原始证据，输出候选提交边界和受影响范围，经显式运维确认后在新文件中建立可恢复前缀；修复不能声称缺失后缀从未被确认。
- 在可控故障注入环境中，已知仅发生尾部未完成写入时可验证截断算法；这不构成生产环境自动判定依据。若未来要求自动修尾同时发现全部已确认尾部丢失，需另行设计独立持久证据或副本的提交协议。
- 无任何破损迹象的完整前缀也不能证明历史末端未曾被整段删除；本地单副本不承诺检测所有历史回退。备份清单/外部确认游标发现领先位置时必须停止自动恢复。硬件遵守同步承诺、无确认后数据破坏是本地耐久保证的前提。

## 7. 进程内执行的持久语义

执行任务：[F11](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f11)、[F12](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f12)。本节规定业务保证，二期传输只包装这些保证。

<a id="plan-s7-1"></a>
### 7.1 保证与故障边界

主进程已返回持久提交结果的事实，在约定故障模型内可恢复；节点完成只在声明的审计前缀及输出完整持久后生效。任务刚生成、尚未提交的内容可能在整进程崩溃时丢失；无法证明封口则该 dispatch 完整性记为 unknown/incomplete。业务状态与审计完整性分开，旧尝试的缺口不因重试成功而消失。

不可承诺任意强杀下所有原始响应零缺口。若要求来源端生成后绝不丢失，须另行具备可靠保留/结果查询能力；不能以进程内队列或未来 IPC 代替。观测数据丢弃不参与本节完整性判定。

<a id="plan-s7-2"></a>
### 7.2 内部提交与结果屏障

1. 主协调器持久记录节点执行开始与 dispatch_id，预留活跃任务和生产预算，再调用现有进程内执行代码。
2. 任务准备实际输入，提交 InputPrepared 并等待内部持久回执；已有已提交实际输入时直接复用，不重算时间/随机模板。原始 run 输入、前驱值和展开参数/版本均在记录或已提交引用中。
3. 权威事实经有界内部提交门面提交，使用 `(dispatch_id, audit_seq)` 连续序号；同序号同内容幂等，异内容拒绝。调用完成仅证明持久化，不授权新的外部操作。
4. 结果提交前停止本任务生产者，封口到 N；N 不得小于该派发已接受的执行审计范围。主进程核验身份、审计 1..N、输入关联和全部输出块，再用同一事务发布固定值描述与节点结果，或登记持久等待。同派发重复提交相同结果返回原提交，异内容拒绝。准备失败可提交原始输入和异常证据，不补造求值结果。
5. 等待登记只结束活跃任务，不冒充节点成功；后续唤醒由主协调器推进。取消与结果串行裁决，取消胜出后结果不推进 DAG，允许的迟到审计只作证据。

上述 await/返回值是进程内调用语义，不序列化 AuditBatch/AuditAck/ResultCommitted，不建立发送窗口或会话重连。二期才定义这些消息。主进程直接处理固定控制节点时同样保存实际输入/输出，以事务 lsn 定位。

<a id="plan-s7-3"></a>
### 7.3 单外部操作授权

一期每节点只支持一个外部逻辑操作，JS 不开放网络入口。HTTP/LLM/email 适配器经内部 `authorize_operation` 门面，引用已提交 InputPrepared，主进程核验 operation_id、实际请求与指纹，并与取消串行裁决。**OperationIntent 与 OperationAuthorized 写入同一事务**；fsync 后内部调用返回授权结果，适配器再次核对任务仍可执行才调用。持久审计回执不能替代这个授权结果。

同请求附着原裁决，同身份异指纹拒绝；适配器对当前尝试的 permit_id 只消费一次，内部请求重试不重复调用，重启后不凭旧授权自动续跑。取消先提交则只保存适用的请求/拒绝证据，不授权。取消前已授权的请求仍可能生效，不承诺瞬间撤销。响应流、OperationOutcome 和节点输出完整保存；超限/中断保留已捕获前缀与未知事实，不当作外部操作未发生。

有完整 Outcome 时复用；已授权无 Outcome 时通过原 operation_id 核对，或仅依外部明确幂等保证重试，否则保留 Uncertain/人工裁决。授权身份随业务尝试绑定，一期无 socket 会话字段；二期增加传输绑定但不改变本规则。

## 8. 一期资源预算

F02 固定一期预算，F07 验证提交器，F17 验证真实进程内执行链路：

| 资源 | 一期约束 |
| --- | --- |
| 在飞 run | `R_max ≥ 1000`，包括等待中的 run；状态可卸载到可重建索引 |
| 活跃执行 | `A_max` 为同时占计算/HTTP/准备资源的任务上限，独立于 R_max；等待登记后释放 |
| 权威生产与提交 | 单任务生产上限 + 全局队列字节上限 + 解析/编码预算；队列满等待持久提交或可取消收尾，不丢权威记录 |
| JS / 大值 | 累计 run 输入与前驱的总物化上限、heap/输出/解析深度/解码扩张限额；并发任务的合计内存必须落在进程预算内 |
| 控制与观测 | 控制提交公平调度，观测独立预算并可丢弃，不堵权威生产 |
| API / 查询 | 兼容响应、页/通知、客户端缓存及投影等待者均有字节/数量/期限上限 |

流式 HTTP 捕获、存储、扇出和恢复不随单个对象总量增加常驻 payload；JS 物化只在声明上限内进行，一期计入主进程总 RSS。CPU 超时与等待存储分别记账；取消可唤醒等待队列，不能丢数据后继续执行。

磁盘低水位停止接新任务并背压既有任务；硬故障停止授权与成功确认，不能自动删权威历史腾空间。未合作任务超过收尾期限时停止新的执行并记录未决状态；一期不承诺从同一进程安全强杀该任务。

**一期没有 X_max、IPC 确认窗口 W、输入传输窗口或重传副本预算。** 二期另行定值，不作为 F02 或 F17 的前置条件。

## 9. Driver、父子与持久等待

执行任务：[F12](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f12)。保留现有节点语义和公开 workflow JSON，改造事实来源和等待管理，不在一期迁移到子进程。

<a id="plan-s9-1"></a>
### 9.1 一次节点尝试与恢复

同一尝试的准备和执行共用 dispatch_id；正常准备完成后直接继续，不重新排一个执行任务。Driver 只依已提交状态推导 ready，内部执行端口返回持久结果后才推进 DAG。纯计算可按已提交输入新建尝试，已有 InputPrepared 不重求值；外部调用按 §7.3 核对，旧未决请求不会被新尝试撤销。

主进程恢复只归约事实、重建索引并枚举未完成 run，不现场运行 JS/HTTP 补历史。人工裁决必须入日志。二期在这些身份和事件之上绑定子进程；一期无需提前实现 FD/PID 或传输状态机。

<a id="plan-s9-2"></a>
### 9.2 父子、信号、定时与取消

创建子 run、固定子定义/输入、登记父等待放同一短事务；子完成与父唤醒同事务。登记时已完成的子直接产生可推进事实。父仍有独立分支时继续，全部等待时卸载协调状态，不为每个等待 run 保持线程或周期轮询。

delay 一次固定 wake_at，重启使用剩余时间；human_task 由匹配的持久 signal 唤醒。取消/信号不依赖空闲执行任务额度。父取消先提交意图和有界子取消命令，子树传播可重启续做，不能只发 best-effort 调用或构造无限事务。

同 tick/wake_at 同时到期 N 个 run 时按活跃任务和队列预算准入，事务共享批量 fsync；测量批次和最大唤醒延迟，不用扩大并发掩盖饥饿。一期先验证进程内 HTTP → script → delay → 重启；二期复用相同业务场景验收进程隔离。

## 10. SQLite 投影、查询与公开 API

执行任务：[F09](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f09)、[F14](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f14)。

所有业务修改统一经主进程命令接口。Store 的业务写方法逐步收为投影器内部接口，防止新功能再次绕过日志。

<a id="plan-s10-1"></a>
### 10.1 完整事务投影与一致读取

投影器以完整日志事务为最小应用单位，在同一 SQLite 事务中更新全部相关业务行和 applied_lsn，重复应用幂等。可合批多个完整日志事务，不得因分页、批次字节数或处理时间限制拆开单个日志事务；applied_lsn 指向最后完整事务的结束边界。即使事务只含不投影的审计内容，也只能在完整验证后推进游标。失败回滚整个 SQLite 批次，读者不能看到同一日志事务中的部分变更；需要跨多次 SQL 读取一致状态的查询使用同一读事务。SQLite 使用什么 synchronous 设置只影响投影重建成本，不改变权威提交保证。必须记录 journal_id，拒绝拿别的数据集的游标继续应用。

run.timeline 等组合查询在读事务内取得读边界 `L = applied_lsn`（`L` 表示日志游标），状态、定义和节点结果统一取该提交边界；需要读取 journal 时同样截到 L，不能拼接旧 SQLite status 与最新 journal 节点状态。订阅读取已提交 journal，查询索引落后时先追平或按日志读取，不能把“投影尚无行”当作 run 不存在并结束订阅。启动/重建阶段先建立可服务的投影边界再开放旧查询接口。

<a id="plan-s10-2"></a>
### 10.2 唯一写入成功语义与原提交查询

一期所有公开 RPC 写调用只提供 projected 成功语义：命令在 L 提交后，必须等 `applied_lsn >= L` 才返回原成功响应；幂等重试返回原结果也经过此屏障。适用 workflow/config 创建更新发布删除、run.start 及已应用的 signal/cancel。成功后的 get/list/timeline 至少可见该提交或更晚合法状态，不要求客户携带新字段。信号“已接收”与“已应用”仍按原接口区分。

不开放 `wait_for=durable`、`min_commit_cursor` 或客户端可选择的一致性模式。内部保留有期限、有全局预算的投影等待，查询继续按 §10.1 取得一致读事务；不为首版增加公开读等待参数。相关扩展登记在三期文档的按需清单，不是二期或三期的前置条件。

持久提交后等待投影超时，返回结构化 `COMMITTED_NOT_VISIBLE`：包含 `committed=true`、`commit_cursor={journal_id, lsn}`、原业务结果/对象 ID、已有 request_id（若有）。它不是普通写入失败，也不是未可见的成功。`command.status` 按 cursor 或完整请求身份从 journal 查询原提交，再用 applied_lsn 返回 visible 状态；查询即时报告状态，不新增无限等待模式。原结果不依赖投影行，超时/断连不撤销事实。

F14 web/CLI 识别该错误并有界查询原提交，不自动重提无身份命令。保持 RPC 名称和 run_seq；request_id、审计完整性等可选字段兼容添加。无 request_id 的旧调用保留原非幂等保证，不伪造稳定身份。

<a id="plan-s10-3"></a>
### 10.3 分页、输出引用与客户端迁移

控制状态回放与完整审计阅读分接口，但都来自同一权威流。以下接口为拟实施契约，F02 固定 DTO、错误码和限额，F14 接通服务端及客户端：

| 读取方式 | 返回及兼容边界 |
| --- | --- |
| 旧 `run.events(run_id, from_seq?)` | 不偷偷分页。固定调用时的 durable 边界，返回该边界内从 from_seq（含）起的全部兼容事件；缺省从 1 开始。按序列化后字节与事件数量设响应硬上限，超限返回 `RESPONSE_TOO_LARGE` 及新接口指引，不返回部分数组。允许在此固定上限内组装响应，禁止无界 Vec/JSON 序列化。 |
| 新 `run.events.page` | 使用版本化事件 DTO，值字段为 StoredValue；按原 run_seq 排序，返回 events、next_cursor 和 snapshot_cursor。首次固定 durable 上界，后续不移动上界；next_cursor 为空只表示本次快照读完，不代表 run 已终结。 |
| 新 `run.audit.page` | 按 journal 位置读取原始审计/chunk 与 LateAudit；与普通 Audit 使用相同去重身份，分页返回记录而不重组完整大值。分页规则同上，可另外开启新快照读取之后补到的证据。 |
| `run.get` / `run.timeline` 的 `value_mode=reference` | 显式选择版本化值字段；小值 Inline、大值 Ref，返回 snapshot_cursor，timeline 同时返回该边界的 last_run_seq；展示预览单列且不冒充原值。未选择时保留原值形状，并受兼容响应上限约束；超限明确报错，不能把引用对象悄悄塞进旧 output。完整值另走按 ValueRef 校验的流式下载；该下载接口的读取授权模型由 F02 固定（§5.0 末条），未固定前不得开放。 |

分页游标绑定版本、journal_id、run_id、过滤模式、固定提交上界和下一未扫描位置；恢复时验证绑定、边界和参数，不把游标当授权。数据页同时受记录数和编码字节限额约束，服务端执行硬上限；单条过大时以有界 Ref/chunk 表达。过滤可产生空页，但未扫到上界仍须给出严格前进的 next_cursor。并发写入、结果重传或迟到审计不能使同一快照内重复/漏项；断点读取使用原游标。大整数编码按 §6.2，旧接口维持原编码。

run.subscribe 的旧模式保留原 seq 和终态结束规则，服务端历史补齐改用有界页面；不能因为分页结束就结束活跃 run 的订阅。新增显式 `event_format=v2`、`from_seq` 和控制/审计模式供已升级客户端选择，过滤不重编号；单通知及缓冲按字节有界。旧模式遇到无法在通知上限内还原的原值，需明确报告超限并结束该订阅，不能静默跳过。终态后的 LateAudit 仍走审计查询，不重新打开兼容订阅。

F14 必须迁移 `web/src/api/flow.ts`、monitor 状态/日志读取和 CLI：采用 reference 查询、分页审计及可续接的状态订阅；先建有界订阅缓冲再取 timeline，在 snapshot/run_seq 边界对齐去重，溢出显式重新对齐。展示缓存按字节和条数双限额，旧日志按需翻页，下载保持流式；日志截断仅是展示策略。旧客户端回归覆盖限额内原形状及超限错误，新客户端覆盖多页、断点、慢消费者、大输出和投影超时恢复。必要客户端迁移是本次范围，不顺带重写无关 UI。

## 11. 分段、恢复、备份与完整性验证

执行任务：[F06](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f06)、[F15](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f15)。

- 轮转只在事务边界发生；封口段只读，记录序号区间、摘要与前段身份。
- SQLite 仅索引控制记录和范围位置，不把所有巨量审计 payload 再复制一份入库；按 run/dispatch 的稀疏偏移索引用于读取。
- 检查点记录 reducer 版本、journal_id、已提交边界和状态摘要，临时写入→sync→原子替换→目录同步。
- 检查点是缓存：版本不兼容或校验失败时丢弃重建，不自动修改日志以迎合缓存。
- 快速恢复先核对已知段清单、顺序和检查点所在提交边界，缺段或游标领先不能靠检查点绕过；随后信任已验证的检查点前缀，读取后缀；完整审计 verify 命令逐段逐事务验证。快恢复不声称检查了每个历史字节。
- 备份包含一个已提交边界之前的完整权威段，活跃段只复制确定前缀；SQLite 和检查点可省略。备份完成后必须验证段集合与边界。
- 不因已生成快照就删除权威历史。压缩/远端归档若启用，必须证明内容可完整恢复；第一阶段可只封口和备份，避免边压缩边写入。

## 12. 历史迁移与回退

执行任务：[F01](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f01)、[F16](JSONL_MASTER_EXECUTOR_TASK_LIST.md#task-f16)。

<a id="plan-s12-1"></a>
### 12.1 先盘点，不能伪造旧历史

旧方案曾允许日志预算丢弃、字段截断和弱持久观察日志；因此不能承诺旧数据通过格式转换就变成完整审计。迁移报告必须逐 run 标明已知截断/缺失，以及不可证明完整的旧格式来源。

**特别地：旧日志里没有“节点实际执行输入”。** 现状写入的是 `cap_input_snapshot(&redact_value(&node.params))`（`driver.rs:93,105`），即脱敏后的节点配置预览；上游产出的实际输入从未落盘（§3）。迁移工具**不得**用配置参数、定义重算或任何推断填充该字段——那会制造看起来完整、实则伪造的历史。缺失项按 run 显式列出并标记为不可恢复。

旧 SQLite 中的完整定义、配置和元数据导出为显式 LegacyImport 基线记录，旧 JSONL 原始字节备份，导入事件保留原身份、时间、seq。元数据与日志冲突时生成差异报告，不自动猜测。

<a id="plan-s12-2"></a>
### 12.2 离线切换流程

1. 停止新请求和新派发，等待可完成任务；不可安全结束的运行按旧协议记录并明确人工处理。
2. 停止旧进程、确认旧执行任务及外部请求已按恢复策略处理，取得独占数据锁并备份。
3. 导出 SQLite 与旧 JSONL 盘点清单、摘要、缺失与冲突报告。
4. 导入到全新目录；为旧完成/未完成状态建立映射，不重写原始备份。
5. 从新 journal 单独重建 SQLite；比较 run 数、定义版本、输出、终态、等待和审计范围。
6. 执行抽样和关键 run 的完整重放，审查历史不完整项目后才能批准切换。
7. 原子切换启动配置；新旧写者不得共存。

<a id="plan-s12-3"></a>
### 12.3 回退限制

新系统尚未接收写入时，可以回到原备份。新系统已提交业务操作后，不能直接恢复旧库继续运行，否则会丢掉新事实并重复副作用。此时只允许使用支持新日志格式的旧兼容二进制回退，或停机做显式反向迁移；无法证明安全时修复前进。

## 14. 一期必测故障矩阵

F17 将每行映射到实际测试/证据；局部测试由责任任务先行完成。

| 故障/场景 | 必须结果 |
| --- | --- |
| 单行半写、缺 LF、错误摘要、未知必需事件版本 | 不应用半笔事务；按既定尾部/损坏策略拒绝或只读，不静默跳过 |
| fsync 成功后回执丢失/同键命令在同批到达 | 返回原提交，同身份异参拒绝，无重复 run/信号/授权 |
| 轮转、目录同步故障、缺段或封口段损坏 | 停止确认与新授权，报告位置；不靠检查点绕过缺失 |
| 投影在日志事务中途退出或受批次限制 | 整笔业务变更与 applied_lsn 同时提交/回滚，不见半笔父子状态 |
| 删除 SQLite、检查点、派生索引 | 仅由 JSONL 重建定义/状态/完整值，外部调用次数为零 |
| InputPrepared 提交前/后进程崩溃 | 未提交准备可按纯计算策略新尝试；已提交输入不重新求值，旧缺口不抹除 |
| Intent/Authorized 单行半写、授权后无 Outcome | 不出现半笔授权；未知外部操作按原身份核对，不盲重发 |
| 取消与授权/结果竞争，任务迟到提交 | 串行裁决，不推进已取消 DAG；迟到证据去重，不覆盖旧缺口 |
| 输出缺块、重复异内容、超限、HTTP 无可信长度/解码扩张 | 不发布不完整引用；增量计量并明确失败，保留捕获前缀和副作用未知状态 |
| 扇出/汇合后重启、多输入合计超 JS 预算 | 引用恢复且已完成 HTTP 不重发；超预算在用户代码运行前拒绝 |
| 子先完成/父登记等待相邻、delay 多次重启、重复 signal | 不丢唤醒、不延长 wake_at，信号幂等 |
| 大取消树中途重启、1000 个在飞 run 崩溃 | 有界恢复传播，未完成 run 可枚举，人工介入比例不超目标 |
| 队列满、审计洪泛、慢磁盘/磁盘满 | 有界背压和公平提交，控制不饥饿；不丢权威数据或降低耐久 |
| 暂停投影后的公开写入/查询 | 成功前等可见；超时 COMMITTED_NOT_VISIBLE 可查询原结果，不假 404 或重复写入 |
| 分页并发追加/空页/断点/错游标、大值通知与慢客户端 | 固定上界内不重复漏项，资源有界，旧接口超限明确错误 |
| 观测存储丢弃/损坏、业务键含 token/secret、越权下载 | 观测不影响完整性；业务值不误脱敏，声明凭证不泄漏，读取按授权拒绝 |
| 历史导入冲突/缺输入/中断/已有新写入后回退 | 原备份不变、可重入、缺失显式；不推断填史或恢复旧库丢新事实 |

SIGKILL 不代替断电；短写/同步故障可用注入后端，真实断电在目标环境独立报告。本期不包含 socket、子进程强杀、FD 泄漏、网络重连等测试，它们分别在二期/三期验收。

## 15. 一期容量与性能验收

F02 固定同一硬件、耐久级别下的目标及负载；F07 用真实 JournalWriter 验证，F17 再验证进程内业务、投影和客户端。不用在飞 run 数推导提交频率。

| 负载 | 核心指标 |
| --- | --- |
| R_max ≥ 1000，明确等待比例与低提交率 | run 状态 RSS、每 run 常驻字节、及时提交与恢复 |
| 持续混合控制/审计 | 事务/s、编码 MB/s、大小分布、控制/审计 p99、每批事务/字节与公平性 |
| A_max 个进程内活跃任务 | CPU/HTTP/JS 总内存、生产与提交队列峰值、等提交时间 |
| 同时唤醒 N 个 run | 批次、最大唤醒延迟、无永久饥饿 |
| 大值、长历史与慢客户端 | 流式/物化内存、projected p99、分页/下载、verify/重建/备份耗时 |

通过条件是吞吐、控制/审计提交 p99、公开写入 projected p99、内存、恢复及实际内容核验同时达标。指定高提交率场景采用预先固定的摊销回归阈值；低负载允许单事务批及时提交。记录数据文件/目录 fsync 次数与时延，不采用所有场景十倍摊销、并发增长斜率或微基准上限 80% 门槛。

纯存储压测不能冒充业务执行验收。所有成功尝试审计连续、分块摘要一致、权威丢弃为零；超载明确背压，观测丢弃不影响业务。原始日志、配置与命令基线可复现；预计参数与测量结果分别记录。

提交器不达标先在预算内优化和复测，仍不达标再评审提交域，不预埋分片/WAL。基础期不评估进程槽位、IPC 窗口或网络中继；二期/三期增加对应指标并回归本节，不以降低 R_max 或耐久性完成验收。
