# 后端修复与生产就绪判断

日期：2026-10-19。范围：14 个 Rust workspace crate；按要求排除 `flow-desktop`。本结论评估后端，不替代前端、桌面或部署环境的验收。

2026-10-23：内联 agent 生命周期、资源预算与历史版本加载的后续修复及最新验收，见 [专项记录](plans/2026-10-23-agent-runtime-hardening.md)。下文测试数与原有 180 秒压测保留为 2026-10-19 的历史证据。

## 判断

**核心功能已经形成闭环；目前仍不应无条件标记为 prod ready。**

目标范围是单主、受信任操作者、有界 DAG 和受控业务调用。当前具备版本发布、分支合流、固定子流程依赖、脚本与外部调用、持久人工等待、触发器、业务调用凭据、崩溃恢复、未知副作用裁决、历史回归、证据导出和备份升级。它可以进入受控上线候选评估。

“功能完整”只适用于上述明确合同。它不包含 master 高可用、多租户管理授权、通用动态循环 Agent、任意外部系统恰好一次执行，或 harness 内部每次工具调用的结构化追踪。这些能力没有因本次修复而被实现，现有设计也不承诺它们。

## 已修复

| 原审查项 | 最终行为 | 验证 |
| --- | --- | --- |
| F2 订阅水位 | 区分读到的事件与扫描完成水位；无关写入不再导致空转，关闭的订阅能退出 | 终态 run 后追加无关事务，确认回放完整且服务端释放通知通道 |
| F3 子流程输入 | 根流程和子流程共用输入校验，子流程按钉死的定义合同检查；非法输入不创建子 run | 缺字段、错类型、额外字段、合法输入、大值引用；映射与继承两种入口 |
| F4 JSON 特殊键 | 模板结果使用无原型对象，保留 `__proto__` 等合法键 | 顶层、嵌套、数组与模板替换 |
| F5 harness 回收 | harness 进程组/Job 随任务回收，执行器会话清理覆盖独立 harness 进程组 | 超时、run.cancel、Drop、执行器被 SIGKILL 后的后代标记写入检查 |
| F6 agent 平台引导 | backend 和 agent 使用同一个平台启动函数；非 Unix 使用本地 socket 回连与会话 token | Unix 真进程、远程链路；新增 Windows Job 模块单独交叉检查；完整 Windows 验收仍待完成 |
| F7 CLI 写身份 | 全局 `--request-id`，丢失响应时输出身份及恢复指引，命令 scope 与服务端共用 | 服务端提交后断开 WebSocket；按报告身份查询并重试，只保留一个 run |
| F8 故障矩阵 | 场景串行，等待真实 checkpoint 到达，可按节点暂停确认 | 默认并行测试运行下命中指定故障窗口；不再用 sleep 代替到达证明 |
| F9 E2E 端口 | 服务自行绑定端口 0，harness 使用该 Child 自报的 RPC/HTTP 地址；失败清理进程 | 全部使用通用 Ctx 的端到端测试 |
| F10 Linux 资源 | 枚举所有线程创建的子进程及后代；报告采集支持/完整性/错误 | 已加 Linux/macOS 活子进程采样用例；Linux 原生运行仍由相应平台验收 |

确定性故障验证还暴露并修复了一个生产竞态：**授权已持久化后，取消若先于 Permit 入队提交，原实现仍可能发送 Permit。** 现在先预留有界队列容量，再在同一个决策锁内检查 run/dispatch/permit 身份并入队。已经入队或已发送的外部请求仍按原合同处理，取消不能撤销既有外部效果。

结果确认测试也纠正了一个错误假设：NodeCompleted 和完整 outcome 已持久化后，ResultCommitted 确认消息丢失不能撤销已接受结果。测试按目标节点精确暂停，验证结果事实保留和外部调用不重复，不强行要求 run 失败。

另补齐 `remote-e2e` 集群分支的直接 SQLx 依赖，修正既有严格 clippy 门禁错误。Windows CI 检查不再排除 agent/executor。

## 验证证据

本轮环境为 macOS / aarch64；Rust 依赖按 Cargo.lock 锁定，离线构建。最终结果：

| 验证 | 结果 |
| --- | --- |
| `cargo test --offline --locked --workspace --all-targets --no-fail-fast` | 77 个测试目标，439 项通过、0 失败、11 项忽略 |
| `cargo fmt --all -- --check` | 通过 |
| `cargo clippy --offline --locked --workspace --all-targets -- -D warnings` | 通过 |
| 集群分支严格 clippy（flow-rpc / flow-backend / remote-e2e，`journal-cluster`） | 通过 |
| PostgreSQL 16 容器，`cluster_registry` / `cluster_process` 的 ignored 测试 | 单独启用集群特性并隔离构建目录，8 项通过、0 失败 |
| 确定性故障矩阵（全量测试内亦有执行） | 3 项通过：授权前断线、授权后取消、结果提交后确认丢失 |
| release `flow-capacity soak`，180 秒，最多 4 个并发 run | 提交 883、成功 736、预期取消 147、失败 0、超时 0 |

混合负载包含大脚本输出、高频日志、HTTP、delay、人工任务和取消。其本机观测延迟为 p95 793 ms / p99 1,289 ms；关闭后的子进程列表为空且采集完整，重开约 29 ms。这些数值来自短时回归场景，不能作为生产容量承诺。

**日志完整性有明确限制：** 高频日志工作流每次产生 2,000 条日志，本轮最终采样的 `queue_dropped` 为 263,449，`history_incomplete=true`；保留和存储丢弃计数均为 0。观测日志按既有合同允许有界丢弃，不等同于业务权威事实丢失，但不能宣称提供完整日志审计。若产品要求逐条日志完整留存，当前能力不满足该要求，需要另行定义背压与持久日志合同。

11 项忽略包含供父测试调用的崩溃子进程 fixture，也包含未执行的容量、磁盘耗尽、HTTP 解码膨胀和性能专项。不能把忽略数全部算成缺失功能，也不能将专项验收算作已通过。测试 PostgreSQL 使用 16，本轮没有验证 18。

## 生产发布前尚需完成的证据

- 在实际 Linux 发行目标和文件系统运行全量与故障测试；本机 macOS 通过不等同于 Linux 运行验收。Linux 资源采样新分支需要原生执行。
- Windows 完整构建及真实本地/远程执行、Job 回收验证。本机交叉构建在第三方 C 依赖处缺少 `windows.h`；单独检查新进程管理模块不能替代全链路验收。
- 按实际并发、数据体量和延迟目标运行长期稳定性及容量验收。本次短时混合负载只是回归证据，没有建立生产 SLO；默认测试跳过的容量、磁盘耗尽、解码膨胀等专项不能视为通过。
- 在目标部署环境完成备份恢复演练、磁盘容量与 WAL/历史增长监控。业务事实与正文保留全部，当前没有 TTL/GC；需要明确的磁盘与备份预算。

这些是上线证据和部署约束，不是将已修复问题留待后续。默认管理接口只监听 loopback，外部暴露应按 OPS 的既有合同使用 TLS/认证网关；远程 agent 扩算力而不接管 master 权威。

## 升级约束

新代码和锁定依赖会改变记录在 v2 run 中的运行时身份。发布前应完成旧运行，或保留匹配执行器继续旧运行；不要绕过已有 runtime 校验，不要把不兼容运行改写为业务失败。本次没有修改持久化格式或已发布定义。

Unix 会话/进程组与 Windows Job 管理针对受管理进程。主动脱离会话/作业的 daemon，以及 master 与执行器同时被强杀的故障，应使用部署级进程容器或服务管理器约束；本次回收不构成不受信任原生命令的沙箱。


### 命令值原子性补充（2026-10-23）

大输入与定义使用有预算的匿名暂存文件；值块、发布、业务事实和回执在一次 SQLite COMMIT 中提交。并发幂等、拒绝、调用方取消与 COMMIT 前进程被强杀的场景均有回归验证。暂存文件自动清理；这里不改变历史事实和已捕获外部响应的保留策略，也不提供历史 TTL／GC。
