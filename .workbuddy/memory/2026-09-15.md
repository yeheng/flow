# 2026-09-15

## Flow（Rust 工作流引擎）设计评审 — 以 Linus 视角

产出：`DESIGN-REVIEW.md`（仓库根目录）。

### 项目结构（首次摸底）
DAG 工作流引擎，3 个 crate：
- `flow-engine` — 执行引擎。事件溯源：每次 run 一个 `runs/<run_id>/event.jsonl` 单写者、每事件 fsync。`node_started` 写在副作用之前，崩溃后残留节点按「纯节点重放 / human_task 等待 / 副作用节点人工裁决」三分法恢复。JS（rquickjs）做表达式与脚本求值，前端预览共用。
- `flow-store` — SQLite：workflows / workflow_versions（不可变版本 + checksum）/ runs（状态镜像）。
- `flow-rpc` — jsonrpsee over WebSocket，`StoreObserver` 把引擎状态变化回写 runs 表。

基线：`cargo test --workspace` 29 测试全绿。

### 实测出的 5 个 bug（写临时探针测试跑出来，跑完已删）
1. **B1 重复 signal 打死 run**。`engine.rs:394` 用 `?` 把「节点当前不等待信号」升格为 run 级错误 → 写 `RunFailed`。实测：`phase=Failed, fatal=Some("节点 approve 当前不等待信号")`。修 ~10 行。
2. **B2 恢复后 condition 分支翻转**。`Driver.outputs` 在 `resume_run` 路径被初始化为空表（`engine.rs:251`），`edge_state` 从中读条件真值 → `unwrap_or(false)` → 未选中分支被**执行**。实测：基准 `{end_no:null}` vs 恢复 `{end_no:"small"}`。若该分支有 http_call，恢复会发出本不该发的副作用。
3. **B3 `exec.rs:255` `&text[..512]` 字节切片 panic** → 任务静默死掉、`DriverMsg::Done` 永不发出、`inflight` 仍持有 handle → 停滞检测不触发 → run 永久挂起（实测 3s 后仍 `Running`，日志无终态）。触发：上游返回 >512 字节的中文错误体会 ~2/3 概率命中。
4. **B4 菱形汇聚静默返回 null**。`plan()` 语义为 AND 汇聚，任何一条入边 Unsatisfied 就 skip → 与 condition 端口组合后无法表达分支合流。实测 `validate()=Ok, phase=Succeeded, output=Null`。测试套件全部绕开了汇聚点。
5. **B5 `runs.error` 用 `COALESCE(?, error)` 无法清空** → 成功的 run 永久带「等待人工裁决」假错误；另有 `insert_run` 与 `EventLog::create` 之间崩溃会留下永远卡在 `running`、API 无法清除的行。

### 核心设计判断（写入评审文档）
- 病灶：节点输出有 3 个 owner（`RunState.outputs` / `NodeRecord.output` / `Driver.outputs`），B2 与 O(N²) 深拷贝都源于此。
- `exec.rs:47` 注释写「前驱节点输出快照（决定论输入）」，实际 `nodes_value()` 把所有节点输出都给了 JS → 在标榜确定性重放的系统里，节点输入不确定。
- 引擎把两种业务策略写死：AND 汇聚 + 失败即整单失败。`fatal` 是延迟判决，注定失败的 run 仍会发完剩余副作用。
- `idempotency_key` / `params_hash` 只写不读（已 grep 确认全仓无读取）；`has_side_effect` 在 `model.rs:46` 与 `flow-rpc:587` 两处重复编码且 `matches!` 不做穷尽检查。
- 沙箱实测干净：`globalThis` 无 `os`/`std`/`fetch`/`require`，`(function(){...})()` 包装挡住顶层 `import`。但未设 `set_memory_limit`，脚本可 OOM 进程。
- `cancel` 只实现了 1/5：令牌只用于 `run_delay`；`spawn_blocking` 里的 JS 取消不掉；且 cancel 与 crash 对「副作用是否发生」给出相反答案。

### 约定
- 评审时用**可运行的探针测试**验证假设，而不是只读代码推理；探针跑完删除，不留下必然失败的测试破坏 `cargo test`。
